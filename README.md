# 架空日本地図ジェネレーター

TRPGの舞台になる架空の日本都市を、地形と街の成り立ちから生成する地図エディターです。住宅一軒ずつの建物、道路、川、緑地、鉄道と駅を描きます。React・TypeScript・Viteで実装し、ブラウザー上で動作します。

**[アプリを開く](https://liesegang.github.io/machitsumugi/)**

## できること

- 城下町・門前町・港町・新興住宅地・宿場町・温泉町の6種類から街の成り立ちを選択
- 河川・平野・海岸、市街化の需要、森林、鉄道・駅数・幹線道路、欲しい施設を指定して生成
- 地形の起伏を低地・丘陵・山地から選択。隆起・侵食・堆積を再計算
- 4×3km・8×6km・12×9km、山間集落から大都市、増加・横ばい・減少の人口推移を指定
- 生成中の地形・水系・街路をプレビューし、中止や設定変更後の再生成に対応
- 等高線と地形・建物高さに基づく3D表示
- シードによる再現可能な生成。ドラッグ移動と拡大・縮小で住宅単位の街並みを確認
- レイヤーと配色を切り替え、TRPG用の場所・メモを追加。GM用メモを管理
- PNG（2048・4096・8192px）または拡大に強いSVGで地図全体をダウンロード
- 生成済み地図の形状・履歴・設定・メモ・表示設定をJSONで保存・読み込み。ブラウザー内にも保存
- 年代スライダーで1650～2025年を指定し、当時までの発展を再計算。建物・道路をホバー／クリックして記録された履歴を確認
- 小型LLM（Qwen3 1.7B）をブラウザー内で動かして地理条件に合う候補から地名を選択。案を確認・編集してから表示中の年代へ反映。初回に約1GBのモデル取得とWebGPUが必要

Google Mapsを参考にした読みやすいベクター地図の表示です。Googleの地図データやタイルは利用していません。生成や画像出力に外部APIキーは不要です。

## 使い方

1. 「街をつくる」で成り立ち・名前・地形・交通・施設を設定します。
2. 「生成」で地図を作ります。同じ設定とシードなら同じ街を生成します。
3. 地図を移動・拡大し、レイヤーやメモを調整します。
4. 「画像を書き出す」で地図画像、「設定を保存」で再編集用のJSONを保存します。

GM用ピンは画像出力では初期設定で除外されます。JSONにはGM用ピンやメモも含まれます。新しく街を生成するとピンはリセットされるため、残したい街は先にJSONを保存してください。

ブラウザーのデータ削除やプライベートモードでは自動保存が失われる場合があります。再編集したい街はJSONも保存してください。

## ローカル開発

Node.js 24とnpmを使用します。

```sh
npm ci
npm run dev
```

開発中のコード変更は通知だけ表示し、地図や生成処理を自動で切り替えません。「更新を反映」を押すと最新のコードを読み込みます。生成中は中止または完了してから反映できます。入力中の設定は引き継ぎます。

```sh
# 地形・交通の個別アルゴリズム、保存データなどの検証
npm run test:unit

# 完全な都市生成の統合検証（複数都市・複数シードを実生成）
npm run test:generation

# 全テスト
npm test

# TypeScript検査と本番ビルド
npm run build

# ビルド済みアプリの確認
npm run preview
```

`dist/`が静的サイトの出力先です。GitHub Pages用のbase pathは`/machitsumugi/`です。`.github/workflows/deploy.yml`がmainへのpush時にテストとビルドを実行し、成功した成果物をGitHub Pagesへ公開します。PagesのSourceはGitHub Actionsを使用します。

CIは完全な都市生成をファイルごとの独立ジョブ、個別アルゴリズムの検証を2分割で実行します。公開はビルドとすべてのテストの成功を待ちます。再現性検査も独立した3回の生成を維持しています。

ghqでの取得例：

```sh
ghq get github.com/Liesegang/machitsumugi
```

## 地理と生成ルール

**[エンジン2.1のアルゴリズム、論文、仮定と検証条件](docs/algorithms.md)**

[日本の実地図との10回の比較記録](docs/comparison-review.md)では、生成画像の問題、変更理由、再確認後に残った差を記載しています。
地図を見分けられない品質を達成したという主張ではありません。
2.0で保存した地図は同じ形のまま復元されます。
2.1の生成方法を反映するには「生成」で作り直してください。

発展段階のプリセットと1650～2025年の年代スライダーで、街道から鉄道開通、郊外開発までの変化を確認できます。道路・敷地・建物は建設年を持ちます。

公開資料で説明される都市形成の特徴を参考に、TRPG向けの手続き生成ルールへ簡略化しています。実在都市の再現や、都市計画・災害リスクの検証を目的とするものではありません。

| 街の種類 | 生成の考え方 |
| --- | --- |
| 城下町 | 城郭と緑地を中心に旧市街を形成し、城外の街路・商業地へ展開 |
| 門前町 | 寺社へ向かう参道を主軸に店舗を集め、背後へ住宅地を配置 |
| 港町 | 海岸と港に沿う道路・商業・倉庫、その内陸側に住宅を配置 |
| 新興住宅地 | 整理された街区、駅前の中心、学校と公園を含む住区を形成 |
| 宿場町 | 街道を主軸に細長い市街地と沿道の商業を形成 |
| 温泉町 | 川や谷に沿う街路、温泉施設と宿泊施設の集積を表現 |

参考資料：

- [国土交通省「歴史まちづくり法に基づく5年間の取組み成果」](https://www.mlit.go.jp/toshi/rekimachi/content/001912269.pdf)：城下町・門前町・港町・宿場町の成り立ち
- [国土地理院「地形分類」](https://www.gsi.go.jp/bousaichiri/lc_configuration.html)：山地・台地・低地・水域などの地形区分
- [UR都市機構「多摩ニュータウンの計画」](https://www.ur-net.go.jp/toshisaisei/comp/planning.html)：鉄道・幹線道路と地区センター、住区の学校・公園・緑道の関係

道路幅・建物寸法・駅数・駅間隔は、地図としての見やすさとTRPGでの扱いやすさのための生成パラメーターです。国の評価指標にある「駅の徒歩圏800m」を、駅間距離の規則として使っていません。自然地形や交通網の全ての制約を再現するモデルではなく、個別の鉄道運行、実際の人口予測や洪水計算は扱いません。

## データと利用

生成と編集はブラウザー内で処理します。大きな地図の自動保存にはIndexedDBを使い、小さな地図と旧形式はlocalStorageからも読み込みます。JSONファイルへの保存にも対応します。サーバーへの街のアップロードやユーザーアカウントはありません。

生成した地図画像はTRPGセッション、配布資料、作品などに利用できます。Googleの地図画像ではありません。アプリのソースコードは[MIT License](LICENSE)です。
