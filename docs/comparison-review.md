# 日本の実地図との比較記録

この記録は、エンジン2.0の公開出力にあった不自然さを実地図と比較し、2.1へ修正した過程を示します。
実地図と生成地図を見分けられない品質に達したという判定ではありません。

比較資料は、国土地理院最適化ベクトルタイルから取得した松本、尾道、多摩の建物、道路、水域です。
各4km×3kmを生成地図と同じCanvas描画器で描き直し、地名と施設記号を隠して比較しました。
建物用途が不明な実データは中立色とし、用途色の有無を形状の良否へ読み替えません。
森林や耕地の属性を抽出していないため、実地図の背景色の面積と生成地図の緑地面積は直接採点していません。
建物のタイル境界による分割もあり、抽出件数を目標人口や目標棟数には使いません。

実在地図の地物は比較資料として保持し、架空都市の生成入力へコピーしていません。
以下は実資料を参照した後に、生成画像の観察、原因の特定、コード変更、再生成、再観察を行った10件です。
独立した工程の変更は可能な範囲で地形や道路を固定して比較しました。
並行変更を含む全体出力の件数差は、一つの修正の効果とは扱いません。

| 回 | 生成画像の違和感と原因 | 変更と再観察 |
|---|---|---|
| 1 | 実松本の河道は大曲線と緩い直線が続くが、生成は長い直線を丸くつなぐだけだった。局所曲率だけの試作では格子の小波形を増幅した。 | 河幅単位の曲率平均、上流からの遅れ、等間隔再標本化、谷壁制約を導入した。細かい鋸歯を抑えたが、細支流の単純さは残る。 |
| 2 | 実地図の合流に比べ、支流の末端が上流向きにフック状となる場合があった。接線だけを直した試作では子支流が切れた。 | 親の下流接線へ接続し、全ての子合流点を固定した。画像と独立した接続検査で白い隙間の解消を確認した。 |
| 3 | 尾道と比べ、自然岸が単一の幾何学的な湾頭だった。標高骨格と河口に固定された切り出し位置が原因だった。 | 沿岸支稜と支谷を広域地形へ加え、沖側の岬と隣の湾も入る調査窓へ変更した。複数の岬が現れたが、人工護岸の形は別途必要だった。 |
| 4 | 曲線を増やしても小さな三角形や四角形の街区が反復した。土地需要を全域78m格子で評価していた。 | 中心から周縁へ間隔が変わる不規則な積分点へ変更した。固定ピッチの反復は減ったが、中心部の生活道は疎らなままだった。 |
| 5 | 実地図にある細い裏道が少なく、中心も周縁も街区の奥行きが大きかった。一律42mの接道深度が候補を不要扱いしていた。 | 中心部18〜24m、周縁35〜45mへ分け、短く細い接続路の実採算を評価した。中心の路地は増えたが、街区骨格の接続と密度差は残った。 |
| 6 | 宅地や道路の縁に無用途の白帯が出た。農区の一部が転用されるだけで区画全体を削除し、施設も外接矩形全体を予約していた。 | 実ポリゴンの取得範囲だけを差分し、穴を含む農地を保存した。白帯は減ったが、未開発宅地の奥へ農地が復活する問題を発見した。 |
| 7 | 市街地奥の農地、湿潤河岸、斜面、未耕作地の区別が欠けていた。 | 登録宅地を農地から除き、未開発宅地、草地、湿潤地を実形状で記録した。分類漏れは減ったが、広い草地を着色しただけの場所は改善完了としなかった。 |
| 8 | 遠方の耕地に農道がなく、農区だけが同寸法で並んだ。固定3方向の農道と旧道550m圏の一律農区が原因だった。 | 耕作適地へ旧道から順に接続する農道網と、地区別の寸法、地形と旧道方向を持つ耕区へ変更した。農道から届く範囲だけを耕作し、外縁のまとまりを再確認した。 |
| 9 | 実多摩にある戸建て、細長い共同住宅、大きな商業敷地の混在がなく、階数だけ違う同寸法の建物が多かった。 | 年代、駅距離、道路役割、計画住区に応じて敷地と足形を変えた。固定道路の新興住宅地で500m²超の建物は2棟から47棟となった。実物の団地や商業街区の構成までは再現できていない。 |
| 10 | 生成は公道の一列目で宅地が止まり、深い街区の裏を使えなかった。 | 十分な奥行きと独立した2.8m通路が成立する場合だけ旗竿敷地を分割した。固定道路で開発済み裏宅地76〜77区画を確認した。中心密度の不足はこの処理だけでは解決しない。 |

回数には、実資料を見る前に行った幹線の線形修正、二値海岸の廃止、32回の侵食更新を含めません。
生成に失敗して画像が得られなかったクリッピング実行も数えません。
鋸歯状の河道や合流切断を生んだ試作は不採用として記録し、修正後を再確認しました。

10件の後にも、森林の水玉を縮尺に応じた低コントラスト表示へ変更し、城門近傍の町割、道路名の違いで生じる主要道路の接線切れ、人工岸と港への道路を追加検査しています。
これらは上表の10件へ追加計上しません。

港は自然岸の形を描き替えるだけでなく、1920年の取得・埋立事業として統合しました。
街道・鉄道と都市の道路網を自然地形で計算した後、その年までに存在する街路へ接続できる場合だけ、海面から造成地を差し引き、岸壁、構内道路、荷捌き場と倉庫を作ります。
河口や崖で条件が成立しない場所を、港のために強制的に造成しません。
造成前の森林と元の斜面を古い敷地の判定へ残し、将来の伐採・平坦化・埋立が1920年以前の住宅を増やさないようにしました。
取得、道路、倉庫の年を記録し、旧建物の用地取得も建物側の年代計算で扱います。
これは固定年の小規模造成シナリオで、港完成後の産業需要まで都市成長へ戻す計算や、実際の港湾工事の再現ではありません。
最終統合の生成画像と検証結果は、個別変更の比較とは分けて確認します。

残る差は、中心街の密度と用途の集積、団地や大型施設の一体的な配置、実際の護岸と用水路改修、地籍に沿う細かな敷地形状です。
数値検査の通過や、無分類の地面が減ったことを「実在地図と見分けがつかない」根拠にはしません。

出典：[国土地理院最適化ベクトルタイル](https://github.com/gsi-cyberjapan/optimal_bvmap)。
実資料を同じ配色へ変換した比較画像には、この出典を付記します。
地形計算の式、採用範囲、未実装の現象は[生成エンジンの設計](algorithms.md)に記載しています。
