# 参考サイトの鉄道と本アプリの修正

2026年10月23日に、[Kakuuzu](https://kakuuzu.jp/)の実際の4km生成結果と、ブラウザーへ公開配信される[鉄道の実装](https://kakuuzu.jp/js/rails.js)を調査しました。
調査用ファイルは開発時の作業領域に保持し、本リポジトリへソースを転載していません。

## 参考で成立している関係

- 複数の既存集落から需要と都市間距離で本線の接続先を選ぶ。
- 近隣の港・市場へは本線を寄せ、徒歩圏のために短い支線を作らない。
- 駅用地と地域の入口・出口を二次元の地形費用探索で結ぶ。
- 山地、勾配、深い市街地、河道直近の低地に建設費を与える。
- 平滑化の後も海・湖と曲率を検査し、駅前後にはホームに必要な直線を取る。
- 分岐は未供給の都市間需要がある場合に限り、結節駅の外側の喉部から接線方向へ分かれる。

## こちらにあった欠陥

従来の本線は北から南へ100m刻みで進み、すべての列で`origin.x - 650`に近い位置を好む探索でした。
地域の行き先が入力されていないので、同じx座標の直線が最小費用になりました。
その欠陥を短いC字の支線で補おうとした変更も不適切でした。
本線駅の徒歩圏に別の一駅支線を作り、同じ需要を重複して使っていました。

## 独立した実装での変更

`railway-corridor.ts`で、鉄道開通以前の集落と乾いた谷出口から本線の回廊を選びます。
回廊の軸へ座標を変換してから、曲率・勾配・軌道標高を持つ線形を設計します。
地形と行き先が直線を許す場合は、見た目のために曲げません。
4×3kmでは短い支線を追加せず、より広い地図でのみ未供給需要を調べます。
本線駅で既に満たすアクセスを便益から差し引き、重複需要や大きな迂回を持つ事業を棄却します。
駅の候補は線路上の乾地にあるだけでは足りず、街路から物理的に到達できる経路を検査します。

最小半径150m、勾配3.5%、通常切盛12mなどは、このアプリの架空の地方鉄道の設計仮定です。
幾何制約を通ったことだけで、日本の鉄道らしい路線網が完成したとは判断しません。
